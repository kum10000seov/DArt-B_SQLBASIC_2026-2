# SQL JOIN 정리

> **JOIN은 연결 조건을 기준으로 여러 테이블의 행을 조합하여, 필요한 정보를 함께 조회하는 SQL 문법이다.**
>
> 핵심은 **테이블의 구조 → 연결 관계 → 유지할 데이터 → 연결 조건**을 순서대로 파악하는 데 있음.

---

## 01. JOIN 기본 개념

JOIN은 여러 테이블에 나뉘어 저장된 데이터를 연결하여 하나의 조회 결과로 구성하는 문법이다.

단순히 테이블을 붙이는 것이 아니라, **연결 조건을 만족하는 행끼리 조합하는 연산**으로 이해해야 함.

| 개념 | 설명 |
| --- | --- |
| Table | 데이터를 행과 열로 저장하는 구조 |
| Row | 테이블에 저장된 개별 기록 |
| Column | 각 기록이 가진 속성 |
| JOIN Key | 테이블 간 대응하는 행을 찾는 기준 컬럼 또는 컬럼 조합 |
| JOIN 조건 | 어떤 행끼리 연결할지 판단하는 조건 |

### 핵심 원리

- 조건을 만족하는 행끼리 연결함.
- 하나의 행이 여러 행과 연결될 수 있음.
- 연결되지 않은 행의 유지 여부는 JOIN 종류에 따라 달라짐.
- 결과에 표시할 컬럼은 `SELECT`에서 별도로 지정함.
- JOIN 자체가 원본 테이블의 데이터를 변경하지는 않음.

> [!IMPORTANT]
> **JOIN 전에는 연결할 컬럼보다 각 테이블의 ‘한 행이 무엇을 의미하는지’를 먼저 확인해야 함.**
>
> 행의 단위를 알아야 연결 관계와 결과 행 수를 올바르게 예상할 수 있음.

---

## 02. JOIN이 필요한 이유

관계형 데이터베이스에서는 데이터를 역할과 관계에 따라 여러 테이블로 나누어 저장하는 경우가 많다.

같은 정보를 반복해서 저장하는 일을 줄이고, 데이터의 수정과 관리를 일관되게 수행하기 위한 구조임.

| 관점 | 설명 |
| --- | --- |
| 데이터 저장 | 역할에 따라 여러 테이블로 분리 |
| 중복 관리 | 동일 정보의 반복 저장을 줄임 |
| 데이터 수정 | 관련 정보를 일관되게 관리 |
| 데이터 조회 | 필요한 테이블을 JOIN하여 정보 결합 |
| 데이터 분석 | 분석 목적에 맞는 데이터 구조로 재구성 |

JOIN은 이러한 **저장 구조와 조회 목적을 연결하는 수단**이다.

분리된 데이터를 필요한 형태로 결합하고, 집계·연산을 추가하여 분석용 테이블이나 데이터 마트를 구성하는 데 활용함.

---

## 03. JOIN Key와 테이블 관계

### 03.1 JOIN Key

JOIN Key는 두 테이블에서 서로 대응하는 데이터를 찾는 데 사용하는 컬럼이다.

일반적으로 식별자인 ID를 사용하지만, 연결 목적에 따라 여러 컬럼을 함께 사용할 수도 있음.

**Key 확인 기준**

- 두 컬럼이 같은 대상이나 관계를 나타내는가?
- 자료형과 값의 형식이 호환되는가?
- Key에 중복값이나 `NULL`이 존재하는가?
- 하나의 컬럼만으로 연결 대상을 구분할 수 있는가?

**컬럼 이름이 같아도 의미가 다르면 연결 기준으로 부적절함.** 반대로 이름이 달라도 의미가 대응하면 연결 가능.

JOIN Key가 반드시 기본키이거나 고유값일 필요는 없다. 다만 **중복 여부에 따라 연결 결과의 행 수가 달라짐.**

### 03.2 테이블 간 관계

| 관계 | 의미 | 결과에 미치는 영향 |
| --- | --- | --- |
| 1:1 | 한 행이 상대 테이블의 한 행과 대응 | 일치하는 행끼리 연결 |
| 1:N | 한 행이 상대 테이블의 여러 행과 대응 | 한쪽 정보가 여러 행에 반복될 수 있음 |
| N:M | 양쪽의 여러 행이 서로 대응 | 행 조합이 늘어나 결과가 크게 증가할 수 있음 |

여기서 관계는 **사용하는 JOIN Key를 기준으로 판단**함.

> [!CAUTION]
> **Key가 중복되면 조건에 맞는 모든 행 조합이 생성됨.**
>
> JOIN 후 행 수 증가가 의도한 관계 때문인지, 잘못된 Key나 누락된 조건 때문인지 구분해야 함.

### 03.3 연결 조건의 범위

JOIN 조건은 값이 같은지 비교하는 방식에만 한정되지 않는다.

- 하나의 컬럼이 일치하는 조건
- 여러 컬럼이 동시에 일치하는 조건
- 특정 날짜나 값이 일정 범위에 포함되는 조건
- 연결 조건에 추가적인 제한을 결합한 조건

복수 조건이나 범위 조건을 사용하더라도, 한 행이 여러 행과 연결될 가능성은 별도로 확인해야 함.

## 04. JOIN의 종류

| JOIN | 결과에 유지하는 데이터 | 연결되지 않은 부분 |
| --- | --- | --- |
| `INNER JOIN` | 양쪽에서 조건이 일치하는 행의 조합 | 제외 |
| `LEFT JOIN` | 왼쪽의 모든 행과 연결되는 오른쪽 행 | 오른쪽 컬럼을 `NULL`로 표시 |
| `RIGHT JOIN` | 오른쪽의 모든 행과 연결되는 왼쪽 행 | 왼쪽 컬럼을 `NULL`로 표시 |
| `FULL OUTER JOIN` | 일치하는 조합과 양쪽의 미연결 행 | 상대쪽 컬럼을 `NULL`로 표시 |
| `CROSS JOIN` | 두 테이블의 모든 행 조합 | 일치 여부를 구분하지 않음 |

### 04.1 INNER JOIN

양쪽 테이블에서 **연결 조건을 만족하는 행만 조합**하는 방식이다.

- 어느 한쪽에만 존재하여 연결되지 않는 행은 제외됨.
- 연결되는 데이터만 분석할 때 사용함.
- 중복을 자동으로 제거하지 않음.

‘교집합’은 기억을 돕는 표현이다. 실제 결과는 공통 Key 목록이 아니라 **조건에 맞는 행들의 조합**임.

### 04.2 LEFT JOIN

**왼쪽 테이블의 모든 행을 유지**하면서 오른쪽 정보를 연결하는 방식이다.

- 왼쪽 테이블이 행 유지의 기준이 됨.
- 오른쪽에 일치하는 행이 없으면 오른쪽 컬럼을 `NULL`로 채움.
- 오른쪽에 일치하는 행이 여러 개면 왼쪽 행도 여러 번 나타남.

**왼쪽 행을 모두 유지한다는 의미이지, 결과 행 수가 왼쪽과 같다는 의미는 아님.**

### 04.3 RIGHT JOIN

**오른쪽 테이블의 모든 행을 유지**하면서 왼쪽 정보를 연결하는 방식이다.

- LEFT JOIN과 행 유지 방향이 반대임.
- 왼쪽에 일치하는 행이 없으면 왼쪽 컬럼을 `NULL`로 채움.
- 테이블 위치를 바꾸면 LEFT JOIN으로 같은 연결 관계를 표현할 수 있음.

### 04.4 FULL OUTER JOIN

**양쪽 테이블의 행을 모두 유지**하는 방식이다.

- 조건이 일치하는 행은 서로 연결함.
- 한쪽에만 존재하는 행도 결과에 포함함.
- 연결 상대가 없는 쪽의 컬럼은 `NULL`로 채움.

양쪽 데이터의 일치 여부나 누락 상태를 함께 확인할 때 활용함.

### 04.5 CROSS JOIN

연결 조건 없이 **두 테이블의 모든 행을 조합**하는 방식이다.

- 공통 Key가 필요하지 않음.
- `ON` 조건을 작성하지 않음.
- 결과 행 수는 두 테이블의 행 수를 곱한 값임.
- 가능한 모든 조합을 구성할 때 활용함.

두 테이블의 크기에 따라 결과가 매우 커질 수 있으므로, 실행 전 예상 행 수 확인 필요.

### 문법상 구분

- `JOIN`만 작성하면 일반적으로 `INNER JOIN`을 의미함.
- `LEFT JOIN`과 `LEFT OUTER JOIN`은 같은 의미임.
- `RIGHT JOIN`과 `RIGHT OUTER JOIN`은 같은 의미임.
- `FULL JOIN`과 `FULL OUTER JOIN`은 같은 의미임.
- 조건부 JOIN에서는 `ON`을 사용하거나, 조건에 맞는 경우 `USING`을 사용할 수 있음.
- JOIN 종류별 지원 여부와 세부 문법은 DBMS에 따라 확인 필요.

## 05. JOIN 선택 기준과 기준 테이블

### 선택 기준

JOIN 종류는 **연결되지 않은 데이터를 어디까지 유지할 것인지**에 따라 결정함.

| 목적 | 선택 |
| --- | --- |
| 연결되는 데이터만 필요 | `INNER JOIN` |
| 왼쪽 데이터를 빠짐없이 유지 | `LEFT JOIN` |
| 오른쪽 데이터를 빠짐없이 유지 | `RIGHT JOIN` |
| 양쪽의 미연결 데이터까지 유지 | `FULL OUTER JOIN` |
| 가능한 모든 조합 생성 | `CROSS JOIN` |

### 기준 테이블

기준 테이블(Base Table)은 조회·분석의 중심이 되는 테이블을 뜻하는 실무적 표현이다.

기준 테이블을 정할 때는 다음을 확인함.

- 분석 대상이 되는 집단은 무엇인가?
- 연결 정보가 없어도 결과에 남겨야 하는 대상은 무엇인가?
- 결과의 한 행은 어떤 단위를 나타내야 하는가?

LEFT JOIN에서는 **유지할 대상을 왼쪽에 배치**하면 구조를 이해하기 쉽다.

다만 `FROM`에 작성했다는 이유만으로 해당 테이블의 모든 행이 유지되는 것은 아니다. 실제 유지 여부는 JOIN 종류와 후속 필터 조건에 따라 달라짐.

## 06. JOIN 구성 요소와 작성 흐름

### 주요 구성 요소

| 문법 | 역할 |
| --- | --- |
| `SELECT` | 결과에 표시할 컬럼 지정 |
| `FROM` | 조회를 시작할 테이블 지정 |
| `JOIN` | 연결할 테이블과 연결 방식 지정 |
| `ON` | 행을 연결하는 조건 지정 |
| `WHERE` | 연결 결과에서 남길 행의 조건 지정 |
| `AS` | 테이블이나 컬럼에 별칭 부여 |

### Alias

Alias는 테이블이나 컬럼에 부여하는 별칭이다.

- 긴 이름을 짧게 표현함.
- 컬럼이 어느 테이블에 속하는지 구분함.
- 이름이 같은 컬럼을 명확하게 참조함.
- 여러 테이블을 연결한 쿼리의 가독성을 높임.

테이블에 별칭을 부여했다면 **별칭과 컬럼명을 함께 사용하여 출처를 명확히 표현**하는 편이 좋다.

### 작성 흐름

| 순서 | 작업 | 확인 사항 |
| ---: | --- | --- |
| ① | 조회 목적 정의 | 무엇을 구할 것인가? |
| ② | 테이블 구조 확인 | 각 테이블의 한 행은 무엇인가? |
| ③ | 기준 대상 결정 | 연결되지 않아도 남길 대상은 무엇인가? |
| ④ | JOIN Key 확인 | 어떤 컬럼과 조건으로 연결할 것인가? |
| ⑤ | JOIN 종류 선택 | 어느 쪽의 행을 유지할 것인가? |
| ⑥ | 결과 예상 | 행 수와 반복되는 정보는 어떻게 달라지는가? |
| ⑦ | 쿼리 작성 | 필요한 컬럼과 조건을 명확히 지정했는가? |
| ⑧ | 결과 검증 | 예상한 구조와 실제 결과가 일치하는가? |

## 07. 여러 테이블 JOIN

여러 테이블을 순차적으로 연결하여 하나의 조회 결과를 구성할 수 있다.

각 JOIN은 **앞서 구성된 결과에 새로운 테이블을 연결하는 구조**로 이해하면 됨.

### 핵심 원칙

- 모든 테이블을 최초 기준 테이블과 직접 연결할 필요는 없음.
- 각 테이블의 실제 관계에 따라 연결 Key를 지정함.
- JOIN 단계마다 행이 유지되거나 제외되고, 여러 행으로 늘어날 수 있음.
- 앞 단계의 결과 변화가 이후 JOIN에도 영향을 줌.

### 확인 사항

- 추가하려는 테이블이 조회 목적에 필요한가?
- 어떤 테이블의 어떤 Key와 연결되는가?
- 연결 Key에 중복이 존재하는가?
- 중간 결과의 행 수가 예상대로 변하는가?
- 서로 다른 JOIN 종류를 섞으면서 필요한 행이 제외되지는 않는가?

JOIN이 많아질수록 연결 관계와 결과 구조를 파악하기 어려워진다. 필요한 테이블만 연결하고, 실제 JOIN 수와 실행 자원 제한은 DBMS 기준으로 확인함.

---

## 08. NULL의 의미와 처리

`NULL`은 값이 없거나 알 수 없는 상태를 나타낸다.

| 값 | 의미 |
| --- | --- |
| `0` | 숫자 0 |
| `''` | 길이가 0인 빈 문자열 |
| `' '` | 공백 문자가 있는 문자열 |
| `NULL` | 값이 없거나 알 수 없는 상태 |

### JOIN 결과에서 NULL이 발생하는 이유

- 원본 테이블의 해당 값이 이미 `NULL`인 경우
- OUTER JOIN에서 연결되는 상대 행이 없어 `NULL`로 채워진 경우

따라서 **결과에 NULL이 있다는 사실만으로 연결 실패를 단정할 수는 없음.**

### NULL 확인 시 유의점

- NULL 여부는 `IS NULL` 또는 `IS NOT NULL`로 확인함.
- 일반적인 등호 조건에서는 양쪽 Key가 모두 `NULL`이어도 연결되지 않음.
- 미연결 행을 찾으려면, 상대 테이블에서 원래 `NULL`이 될 수 없는 식별 컬럼을 기준으로 확인하는 편이 적절함.
- `NULL`을 0이나 빈 문자열로 바꾸기 전에는 해당 값의 의미와 분석 목적을 확인해야 함.

## 09. JOIN에서 자주 혼동하는 부분

### 09.1 ON과 WHERE의 차이

| 구분 | 역할 | 판단 대상 |
| --- | --- | --- |
| `ON` | 연결할 행의 조건 지정 | 어떤 행끼리 연결할 것인가? |
| `WHERE` | 연결 결과의 행 필터링 | 어떤 행을 최종적으로 남길 것인가? |

특히 OUTER JOIN에서는 같은 조건이라도 위치에 따라 결과가 달라질 수 있음.

- `ON`에 조건을 추가하면 해당 조건을 만족하는 행만 연결 대상으로 인정함.
- `WHERE`에 조건을 추가하면 연결 결과에서 조건을 만족하지 않는 행을 제외함.
- 오른쪽 컬럼에 대한 `WHERE` 조건은 LEFT JOIN으로 유지한 미연결 행을 제외할 수 있음.

**연결 조건과 최종 조회 조건을 구분하여 작성해야 함.**

### 09.2 행 수 증가와 중복 합산

JOIN은 조건에 맞는 행을 모두 조합하므로, 결과에서 같은 정보가 반복될 수 있다.

이 상태에서 집계하면 의도하지 않은 중복 합산이나 건수 증가가 발생할 수 있음.

- 결과 행 수와 고유 ID 수를 구분하여 확인함.
- 결과의 한 행이 어떤 단위인지 다시 확인함.
- 집계할 값이 JOIN 과정에서 반복되었는지 확인함.
- 행 수가 예상보다 많다면 Key 중복과 연결 조건 누락을 점검함.

### 09.3 필요한 컬럼만 선택

모든 컬럼을 조회하면 구조 확인에는 편리하지만, 실제 사용 시에는 필요한 컬럼을 명시하는 편이 좋다.

- 결과의 의미와 컬럼 출처가 명확해짐.
- 동일한 이름의 컬럼으로 인한 혼동을 줄임.
- 불필요한 데이터 조회와 처리를 줄일 수 있음.

> [!TIP]
> **BigQuery에서는 필요한 컬럼만 조회하여 처리량을 줄일 수 있음.**
>
> 사용량 기반 과금에서는 비용 절감에도 도움이 된다.
> `LIMIT`은 출력 행 수를 제한하므로, 이것만으로 읽는 데이터량이 줄어든다고 가정하면 안 됨.

---

## 10. JOIN 핵심 정리

JOIN을 작성할 때는 다음 다섯 가지를 중심으로 판단함.

| 구분 | 핵심 질문 |
| --- | --- |
| 목적 | 어떤 정보를 얻으려는가? |
| 구조 | 각 테이블의 한 행은 무엇을 의미하는가? |
| 관계 | 어떤 Key로 연결되며, 중복은 얼마나 존재하는가? |
| 유지 조건 | 연결되지 않은 행을 어디까지 남길 것인가? |
| 검증 | 결과의 행 수와 집계값이 의도에 맞는가? |

### 최종 확인

- 결과의 한 행이 무엇을 의미하는지 정했는가?
- 연결되지 않아도 유지할 대상을 정했는가?
- Key의 의미·자료형·중복·NULL 여부를 확인했는가?
- 한 행이 여러 행과 연결될 가능성을 고려했는가?
- `ON`과 `WHERE`에 조건을 의도대로 배치했는가?
- 결과 행 수, 고유 ID 수, 미연결 행을 확인했는가?
- 집계 대상 값이 중복 계산되지 않는지 확인했는가?

> **JOIN의 핵심 = 테이블 구조 파악 + 연결 조건 설정 + 행 유지 방식 결정 + 결과 검증**
